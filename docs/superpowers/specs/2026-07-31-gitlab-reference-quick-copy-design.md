# GitLab Issue/MR 编号快速复制设计

## 1. 背景与目标

现有扩展会在 GitLab Issue 或 Merge Request（MR）详情页顶部固定显示当前编号。
本次增加快速复制能力，让用户无需选中文本，即可复制适合粘贴到 GitLab 文本中的
引用格式：

- Issue 复制 `#<iid>`，例如 `#15`。
- MR 复制 `!<iid>`，例如 `!14`。

功能继续兼容 `gitlab.com`、任意 HTTP/HTTPS 自建 GitLab、Chrome 150 和
Arc 1.157.1（Chromium 150），且不新增扩展权限、网络请求或持久化行为。

## 2. 方案选择

采用类似 GitHub 仓库地址复制控件的紧凑分段样式：左侧显示编号，右侧常驻独立
复制按钮，两者共用外框并以细竖线分隔。

相比让整个标签都可点击，该方案能明确区分“查看编号”和“执行复制”，也能提供
标准按钮语义、键盘操作和独立焦点样式。相比点击后弹出额外 Toast，直接将图标
切换为绿色对勾可以就地反馈，视觉变化小，不增加页面覆盖区域。

## 3. 用户界面

标签仍固定在视口顶部中央，并保留现有 Issue/MR 文案和浅色、深色主题适配：

- Issue 显示 `Issue #15`。
- MR 显示 `MR !14`。
- 复制按钮始终显示复制图标。
- 编号区域与复制按钮之间显示一条低对比度分隔线。
- 复制按钮悬停时使用轻微背景色变化，键盘聚焦时显示清晰焦点轮廓。

复制按钮使用原生 `<button type="button">`，并提供随当前引用更新的无障碍名称，
例如 `复制 #15` 或 `复制 !14`。图标使用内联 SVG，只表达操作或状态，不依赖外部
图标资源。

标签 host 继续使用 `pointer-events: none`，只有复制按钮设置
`pointer-events: auto`。因此按钮本身可以操作，而标签周围及编号区域不会拦截
GitLab 顶栏上的下层控件。

## 4. Tooltip 与反馈状态

复制按钮在鼠标悬停或键盘聚焦时，于按钮下方显示 tooltip。放在下方可以避免标签
贴近视口顶部时被裁切。

状态文案如下：

| 状态 | Issue tooltip | MR tooltip | 图标 |
| --- | --- | --- | --- |
| 默认 | `复制 #15` | `复制 !14` | 复制图标 |
| 成功 | `已复制` | `已复制` | 绿色对勾 |
| 失败 | `复制失败` | `复制失败` | 复制图标 |

点击成功后立即进入成功状态，`1500ms` 后恢复默认状态。失败状态也在 `1500ms`
后恢复。连续点击时清除之前的恢复计时器，以最后一次操作为准。

Tooltip 仅作为补充反馈，不承担唯一的无障碍通知职责。Shadow DOM 内设置独立的
视觉隐藏 `aria-live="polite"` 状态节点，同步播报 `已复制` 或 `复制失败`；编号
正文不再承担 live region 职责，避免普通同步时被重复朗读。按钮的无障碍名称在
默认状态下始终说明将复制的具体引用。

## 5. 复制流程与降级

点击复制按钮后执行以下流程：

1. 根据当前解析结果生成复制文本：Issue 为 `#<iid>`，MR 为 `!<iid>`。
2. 若 `navigator.clipboard.writeText` 可用，优先调用该 API。
3. 若 Clipboard API 不可用或调用失败，使用临时、不可见的文本输入节点配合
   `document.execCommand('copy')` 降级复制。
4. 任一方式成功则显示成功状态；两种方式均失败则显示失败状态。
5. 无论成功或失败，都不抛出未处理异常，也不影响 GitLab 页面功能。

降级路径用于兼容 HTTP 自建 GitLab 等可能不具备安全上下文 Clipboard API 的环境。
临时输入节点只在复制过程中存在，完成后立即移除。

## 6. 生命周期与导航

内容脚本继续通过现有 `sync()` 流程响应首次加载、浏览器导航事件、GitLab/Turbo
事件和 DOM 变化。

每次同步到新的有效 Issue/MR 时：

- 更新显示文案和复制文本。
- 更新按钮的无障碍名称与默认 tooltip。
- 清除上一个页面遗留的成功、失败状态及恢复计时器。

离开 Issue/MR 详情页或调用 `destroy()` 时，移除标签并清理反馈计时器、事件监听和
观察器，避免后续异步回调重新修改已销毁界面。

## 7. 实现边界

改动集中在现有内容脚本及其测试中：

- `src/content.js`：渲染分段控件、生成复制文本、执行复制、管理 tooltip 和反馈状态。
- `tests/content.test.js`：扩展最小 DOM 夹具并覆盖复制与状态生命周期。
- `tests/browser.test.js`：验证真实 Chromium 中按钮命中、鼠标交互、剪贴板结果和
  SPA 导航后的状态。
- `README.md`：说明快速复制格式和交互方式。
- `docs/testing.md`：记录新增自动化断言与手工验收项。

本次不增加设置页、复制格式选项、快捷键、Toast、操作历史或扩展权限。

## 8. 错误处理

- Clipboard API 抛出异常时自动尝试降级复制。
- 降级复制返回 `false` 或抛出异常时进入失败状态。
- 复制过程中发生 SPA 导航时，新页面同步会使旧操作结果失效；旧 Promise 完成后
  不得覆盖新页面的按钮状态。
- `destroy()` 后完成的异步复制不得重新创建或更新标签。

为避免异步竞态，每次同步和销毁都会使之前的复制操作失效，只有仍属于当前页面和
当前标签实例的操作结果可以更新界面。

## 9. 测试与验收

### 9.1 单元测试

至少覆盖：

- Issue 点击后请求复制 `#15`。
- MR 点击后请求复制 `!14`。
- 复制按钮为原生按钮，具有正确无障碍名称。
- 样式声明 host 默认鼠标穿透、复制按钮可接收鼠标事件。
- 默认 tooltip、成功 tooltip 和失败 tooltip 文案正确。
- 成功时图标切换为绿色对勾，并在 `1500ms` 后恢复。
- Clipboard API 不可用或失败时执行降级复制。
- 两种复制方式都失败时不抛出未处理异常，并显示失败状态。
- SPA 导航和 `destroy()` 会清除旧反馈状态，旧异步结果不能污染新页面。

### 9.2 真实浏览器测试

通过现有 WebDriver BiDi 与 Chrome DevTools Protocol 场景验证：

- 标签编号区域仍不阻挡下层页面控件。
- 复制按钮可由真实鼠标命中和点击。
- 悬停复制按钮时 tooltip 出现在按钮下方。
- 点击 Issue 按钮后剪贴板内容为 `#123`，图标变为绿色对勾。
- SPA 切换到 MR 后复制内容更新为 `!456`，且不保留旧成功状态。
- 离开详情页后标签与反馈界面均被移除。

### 9.3 手工验收

在 Chrome 和 Arc 的真实 GitLab 页面中确认：

1. 复制图标常驻显示，整体样式与 GitHub 仓库复制控件相似但仍匹配现有标签配色。
2. 鼠标悬停和键盘聚焦都能看到 tooltip。
3. 点击后可将 `#编号` 或 `!编号` 粘贴到任意文本输入位置。
4. 成功时绿色对勾清晰但不过度醒目，并能自动恢复。
5. HTTP 自建 GitLab 可通过降级路径复制。
6. 顶部导航中除复制按钮自身占用的区域外，其他下层控件仍可操作。

## 10. 完成标准

以下条件全部满足才算完成：

- Issue 和 MR 分别复制 `#<iid>` 与 `!<iid>`。
- 复制图标常驻，悬停或聚焦显示 tooltip。
- 成功后显示绿色对勾并自动恢复，失败时显示明确反馈。
- HTTP 自建 GitLab 具备可用的复制降级路径。
- 鼠标、键盘和屏幕阅读器均能理解并操作复制按钮。
- SPA 导航和销毁过程中无陈旧状态或异步竞态。
- 单元测试、真实 Chromium 测试和文档更新全部通过。
